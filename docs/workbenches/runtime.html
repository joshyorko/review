Auto follows the image type and host prerequisites

For an OCI image, Auto prefers Podman + krun + KVM when those checks pass; if they do not, it reports the missing prerequisite and attempts Apptainer when its own requirements pass. A SIF uses Apptainer directly. If no path qualifies, launch stops.

03 / Boundaries

Read the gate correctly

Runtime selection, verifier qualification, work admission, and GitHub authority are separate checks.

Missing runtime prerequisites

For OCI, Auto prefers krun and attempts Apptainer only when krun prerequisites are missing and Apptainer's own requirements pass. A SIF uses Apptainer directly. Explicit krun never falls back.

Failed Factory verifier

When Factory is enabled, a failed bubblewrap or harmless sandbox check blocks Factory-enabled startup before OMP opens. This is separate from runtime fallback.

Permissions and admission

GitHub remains authoritative for repository access and rules. Factory enablement is not batch admission, and neither workbench grants merge or deployment authority.
